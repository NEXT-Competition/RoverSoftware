01 one control tick

Every tick is a four-stage pipeline.

The ControlManager calls update(dt) ~50 times a second. Sensing is injected, so the same logic runs on a laptop with no hardware attached.

STAGE 1

Sense

Read the current fix from the injected pose provider.

→ lat, lon, heading
STAGE 2

Arrived?

Distance to the target waypoint vs the arrival radius.

→ advance or steer
STAGE 3

Steer

Bearing − heading, fed through a PID controller.

→ steer ∈ [−0.7, 0.7]
STAGE 4

Mix

Blend forward speed and steer into track speeds.

→ left, right

02 what goes in

Two inputs: a pose, and a route.

The pose provider — a callable, injected once GPS is wired up:

pose() → (lat, lon, heading_deg)  |  None

None means no fix — the controller holds still. Heading is 0° = North, clockwise positive.

The route — pushed live from the base station over the radio:

{ "type": "route",
  "waypoints": [[lat, lon], [lat, lon], …] }

on_message() swaps the list in and resets to leg 0.

⚠ heading caveat

The NEO-6M has no compass. Its only heading is course over ground — the direction you're actually moving — and that's meaningful only while moving.

standstilllast known course
below 0.5 m/scourse = noise, held
first legsteers rough, then locks in

The PID self-corrects as soon as real motion produces a course.

03 stage 2 · arrived?

“Am I there yet?” — haversine distance.

Great-circle distance between two lat/lon points on the Earth's surface, in metres. When it drops inside the arrival radius, the controller advances to the next leg.

a = sin²(Δφ/2) + cos φ₁·cos φ₂·sin²(Δλ/2)
d = 2 · R · asin(√a)   R = 6 371 000 m
arrive_radius = 2.0 m then idx += 1, PID reset 
if haversine_m(lat, lon, tlat, tlon) <= arrive_radius_m:
    self._idx += 1            # next leg
    self.heading_pid.reset()  # fresh integrator
    return DriveCommand.stopped()  # pause a tick

A one-tick stop between legs prevents a jerky pivot as the target flips.

04 stage 3a · which way

“Which way is the target?” — initial bearing.

The compass direction from the rover to the target, accounting for the fact that lines of longitude converge. 0° = North, clockwise positive.

y = sin(Δλ) · cos φ₂
x = cos φ₁·sin φ₂ − sin φ₁·cos φ₂·cos(Δλ)
bearing = atan2(y, x)  → normalized 0–360°

This is the target direction. On its own it says nothing about where the rover is pointed — that's the next step.

05 stage 3b · steer

Heading error → PID → steer.

Subtract heading from bearing to get the error — but wrapped to the shortest signed turn, so a 350° target becomes a −10° nudge, not a 350° spin.

def _heading_error_deg(target, current):
    # smallest signed angle, [−180, 180]
    return (target − current + 540) % 360 − 180
kp 0.02 ki 0.0 kd 0.005 clamp ±0.7

Why these gains?

P · 0.02°error → steer
I · 0off — no wind-up drift
D · 0.005damps the overshoot
out_limitnever turns flat-out

A ~35° error saturates steering; small errors trim gently. The result is steer ∈ [−0.7, 0.7].

06 stage 4 · arcade mix

Slow down to turn, then mix into tracks.

Forward speed drops as steering grows, so the rover doesn't overshoot the line on a hard turn — but never stalls below 20% of cruise.

forward = cruise_speed * max(0.2, 1.0 − abs(steer))
return DriveCommand.arcade(forward, steer)

cruise_speed = 0.35 · arcade() → (left, right) track speeds

What arcade mixing does

steer 0.0L = R  (straight)
steer +0.4L > R  (veer right)
steer +0.7slow + hard right

left = forward + steer  ·  right = forward − steer, each clamped to the track limits.

07 all together

The whole tick, top to bottom.

def update(self, dt):
    # failsafes first
    if pose_provider is None or done:
        return DriveCommand.stopped()
    pose = self.pose_provider()
    if pose is None:
        return DriveCommand.stopped()   # no fix

    lat, lon, heading = pose
    tlat, tlon = self.waypoints[self._idx]

    # stage 2 — arrived?
    if haversine_m(…) <= arrive_radius_m:
        self._idx += 1; pid.reset()
        return DriveCommand.stopped()

    # stage 3 — steer
    err  = _heading_error_deg(bearing_deg(…), heading)
    steer = self.heading_pid.update(err, dt)

    # stage 4 — mix
    forward = cruise * max(0.2, 1 − abs(steer))
    return DriveCommand.arcade(forward, steer)

The controller never talks to a motor or a radio directly. It only reads a pose and returns a DriveCommand — which is exactly why it runs, and tests, with no hardware at all.
